# Code smells — Lab 12

Catalog **≥8** smells from the messy baseline (`doStuff`). Tie each to CRM impact (CUS-1001).

| # | Smell                                | Location          | Impact on CUS-1001                                                                                                                                                                                                                              |
|---|--------------------------------------|-------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 1 | Poor naming (`doStuff`, `data`)      | lines 11,13,26    | these vague names make it hard for other programmers to understand what these variables/functions do                                                                                                                                            |
| 2 | Raw types                            | line 11           | by using raw types, there are now more edge cases for programmers to check                                                                                                                                                                      |
| 3 | Long method / mixed responsibilities | line 13           | having such a long method makes it harder for other programmers to decipher the point of the method, and for general debugging purposes. Having the method both update and create also means that there are more edge cases for both scenarios. |
| 4 | Stringly-typed status                | line 13           | this adds more edge cases for programmers                                                                                                                                                                                                       |
| 5 | Incorrect equality (`==`)            | lines 15, 55      | this has a huge impact, since this type of equality check only compares the references, and not the actual content. This means that this will be true when it should be false, and vice versa.                                                  |
| 6 | Null as control flow                 | lines 31-24, 39   | this makes it tough for programmers to debug why certain values are null.                                                                                                                                                                       |
| 7 | Side-effect logging                  | lines 16,22,38,45 | This type of logging will only confuse other programmers working on the project; it's not detailed nor does it specify what's wrong.                                                                                                            |
| 8 | Magic `"UPDATE"` behavior            | line 39           | this will make it harder to figure out when customers get updated, and it also is very limited in terms of updating.                                                                                                                            |
